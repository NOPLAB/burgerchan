# Burger前方用 HC-SR04マウント

HC-SR04を2個、TurtleBot3 Burgerの前方に沿って取り付ける治具。
`burger_sensor_assembly.solidcraft` で機体との位置関係を確認し、
印刷には `carrier.stl` を1個、`clamp.stl` を4個使う。
組み立てる前に「取り付け方」まで読んでおく。寸法を変える場合は後半を参照。

## 照射側は一体の円弧、基板の固定面は平面

基板前面の設置半径は81.2mm、左右の向きは前方から各30度。
初版の半径97mmから15.8mm縮めた。直前の81mm案からは、
QIコネクタが上段底板を避けられるよう0.2mmだけ外へ寄せている。中心は底板の幾何中心で、
車輪軸中央から後方32mmの位置にある。

照射側の外面は半径88mmの一続きの円弧。左右のセンサーを別々の板で囲う構成をやめ、
一体のカバーに4個の円形開口を設ける。送受信部の先端はカバーより前へ出る。
背面の基板ポケットとナット座は平面を残し、固定面が曲面にならないようにしている。

印刷部品の下端は地上20mm。幅29.6mm、奥行33mmの受け座の下面は22mmに上げ、
公式機体メッシュにある前方ブラケットの上面に合わせている。
底板単体の上面19mmを取り付け面と誤認しないこと。
受け座は厚さ6mmとし、上側の補強リブと下側の回転止めを加えた。
固定ねじは従来どおり2本。受け座の4個の浅い逃げは、既存のねじ頭を避けるためのもので、
新たな固定穴ではない。
カバー上端は地上47.3mmとし、上段底板の下面47.5mmに対して0.2mmの逃げを設ける。

公式機体メッシュ上で、実際に当たる水平面を0.05mm格子で比較すると、
旧タブの約15.9mm²に対して新しい受け座は約251.7mm²で、接触面積は約15.8倍。
下側の回転止めは、水平面とは別に本体前面へ当たる。
これは接触面積の比較であり、剛性や許容荷重が同じ倍率になったという意味ではない。

| 項目 | 設計値 |
|---|---:|
| センサー数 | HC-SR04 × 2 |
| 基板外形 | 45 × 20mm |
| 基板厚 | 1.6mm（仮定） |
| 円筒部の外径 / 中心間隔 | 16 / 26mm（仮定） |
| 円筒部の逃げ穴 | 直径16.8mm |
| 前面壁の厚さ | 基板座の範囲で約4～7mm |
| 基板ポケットの床 / 天井厚 | 最小3.8 / 3.1mm |
| 本体側の受け座厚 | 6mm |
| 基板押さえの厚さ | 2.4mm |
| 機体側固定穴 | 直径3.3mm、左右24mm間隔 |

HC-SR04の公開資料で確認できる外形は45 × 20 × 15mm。
円筒間隔や基板厚には互換品による違いがあるため、上表では仮定を分けて記した。
基板の小さな固定穴は使わず、左右端をクランプで押さえる。

## QIコネクタは最大外形に片側0.2mmの逃げを加える

共立のQI-4図面では、幅10.36mmに対する正側公差が0.36mm、長さは14mmに対して
正側公差が0.3mm。幅は最大10.72mmとして、左右それぞれに0.2mmを加え、
天井の開口幅を11.12mmにした。ピンヘッダーの樹脂部も通るよう、奥行は3.4mm確保する。
端子・コネクタ・配線は上へ逃がす。

図面は `reference/qi_connector.pdf`。組立モデルの黒いQI部品は公称外形、
非表示の `QIKeepout` は公差と逃げを含めた検査用の外形である。
別形状のハウジングを使う場合は `qi_width`、`qi_depth`、`qi_height` を実寸に合わせる。

## 印刷はキャリア1個とクランプ4個

STLの単位はmm。どちらも印刷面がZ=0になる向きで出力してある。
クランプは18.8 × 9.5 × 2.4mmで、4個とも同じ形。

試作時の開始値は、積層0.2mm、外周4周、充填30～40%。
キャリアは平らな下面をベッドに置く。受け座の下面は印刷面から2mm浮くため、
その下面と基板ポケットの天井にはサポートを付ける。
横向きの円形開口も、必要に応じて上部を支える。クランプは広い面を下にする。
実機への試着と印刷精度の確認はまだ行っていない。

## 取り付け方

必要な部品は、印刷したキャリア1個・クランプ4個、HC-SR04 2個、
クランプ用M3 × 12mmねじ4本とナット4個。
機体への固定はM3ねじ2本を使う。受け座が厚くなったため22～25mm長を候補とし、
既存ブラケット・底板・ナットを含む実際の締結厚さに合わせて選ぶ。

1. キャリアを機体前方に置く。固定穴の位置は、車輪軸中央基準で
   `(X, Y) = (32, 12), (32, -12) mm`。Xが前方、Yが左方。
   広い受け座の下面を既存ブラケット上面に、下側の回転止めを本体前面に当て、
   2本のねじで留める。
   穴を既存ねじや配線が占有していないか、締め付け前に確認する。
2. HC-SR04を背面から差し込み、銀色の円筒2本を前面の逃げ穴に通す。
   **4本の端子が上を向く向き**にする。
3. 基板の左右端にクランプを当て、各1本のM3ねじで固定する。
   クランプは基板端の約1mmだけに掛かる。裏面部品を挟まないことを確認し、
   基板が動かなくなるところで締め付けを止める。
4. 配線を上・内側へ引き回し、タイヤや床に触れない位置で固定する。

## 寸法変更と再生成

`sensor_mount.solidcraft` は治具だけの編集用設計、
`burger_sensor_assembly.solidcraft` は公式機体形状とセンサーの概形を含む配置確認用設計。
後者のセンサー裏面部品・端子・ねじ頭は仮の包絡形状で、購入品の精密CADではない。
`carrier.step` と `clamp.step` も編集・受け渡し用に出力している。

SolidCraft 0.19.0では、この形状の交差する円筒面を切削するとブーリアン計算が失敗する。
そのため、曲面の形状計算だけをFreeCAD 1.1.1 / OpenCASCADEで補助する。
`build_carrier.py` が `build_carrier.json` の寸法表からSTEPを生成し、
SolidCraftで取り込んで表示・計測・STL出力する。
SolidCraft内では取り込み済みのソリッドを編集できるが、寸法表だけを変えても本体形状は再計算されない。

作業ディレクトリをこの `mechanism/` にして順に実行する。
以下の実行ファイルの配置は、このPCに導入したもの。
各コマンドが正常終了したことを確認してから次を実行する。
```powershell
$fc = "$env:LOCALAPPDATA\Programs\FreeCAD 1.1\bin\python.exe"
$sc = "$env:LOCALAPPDATA\solidcraft-agent-0.19.0\bin\solidcraft-0.19.0-windows-x64-portable\solidcraft-cli.exe"
& $fc .\build_carrier.py --verify
& $sc run build_carrier.json --save sensor_mount.solidcraft --results --json-out verification/mount_results.json
& $sc run build_assembly.json --in sensor_mount.solidcraft --save burger_sensor_assembly.solidcraft --results --json-out verification/assembly_results.json
& $sc run export_print.json --in sensor_mount.solidcraft --results --json-out verification/print_results.json
```

寸法の入力は `build_carrier.json`、形状の定義は `build_carrier.py`。
JSON先頭の `parameters.add` で基板厚 `pcb_t`、円筒間隔 `can_pitch`、
逃げ穴径 `can_clearance`、ねじ逃げ径 `bolt_d`、左右角度 `sensor_angle`、
QIの追加逃げ `qi_extra` を変更する。
地上高・キャリア厚・円弧半径は機体との当たりを確認した固定寸法。
変更後は補助計算から組立モデルまで再生成し、干渉と印刷向きを確認する。
`--verify` は `parameter_walk.json` の各寸法状態を実際に作り直し、
単一ソリッド、開口、QI逃げ、クランプ・ねじ工具との非干渉を確認する。
寸法変更の検証記録は `verification/source_geometry.json` に出力する。

## 参照した機体データと検証

ROBOTIS公式のBurger機体・車輪・LiDARメッシュと、
公式配布の `TB3_WAFFLE_PLATE-IPL-01` STEP/PDFを `reference/` に保存した。
底板STEPはX軸まわりに90度回転し、`[-32, 0, 19] mm` 移動して登録してある。
組立設計では機体メッシュとの重複表示を避けるため、このSTEP部品を非表示にしている。

出典、固定リビジョン、座標変換、ライセンスは `sources.json` に記録。
機体メッシュの座標は公式URDFに従い、地面をZ=0としている。
モデルは標準機体の公称形状であり、実機の改造部品やねじ頭の違いまでは反映していない。

SolidCraftの干渉計算はSTEPと治具・センサー概形を対象にする。
機体STLはソリッド干渉計算の対象外なので、別途三角形の交差も確認する。
本体に当たる水平面と、回転止めの垂直面は意図した接触として扱う。
接触面積は公式メッシュ上で比較し、意図しない貫通とは分けて記録する。
QIの最大外形に対する逃げと、2本の固定ねじへの工具アクセスも検査する。
接触面を広げて断面を補強した設計だが、荷重試験や有限要素法によるたわみ計算は未実施。
最終モデルでは、組立20ソリッドの干渉と、QI・工具の検査領域を含む9ソリッドの干渉はいずれも0件。
機体メッシュとの検査でも、受け座と回転止めの接触以外の交差はない。
STLは両部品とも閉じた面構造で、面の向きの不整合は0件。

数値は `verification/summary.json` と `verification/mesh_checks.json`、
画像は同じディレクトリの `assembly_iso.png`、`assembly_top.png`、
`assembly_front.png` を参照。

公式SolidCraft skill一式は `../.agents/skills/` に置いてある。
